\\¿Cómo subir una rama local a GitLab?
git push -u origin nombre-de-la-rama
\\ejemplo.
git push -u origin nueva-funcionalidad

Resumen:

Usa git branch para ver ramas locales.
Usa git branch -r para ver ramas remotas.
Usa git branch -a para ver todas.
Usa git status para verificar si tu rama local está vinculada a una remota.
Verificar si el repositorio local está conectado a un remoto
git remote -v

Si el repositorio ya está conectado, verás algo como esto:
origin  https://gitlab.com/usuario/proyecto.git (fetch)
origin  https://gitlab.com/usuario/proyecto.git (push)

Conectar un repositorio local a un repositorio remoto
git remote add origin https://gitlab.com/usuario/proyecto.git
confirmar 
git remote -v

Verificar si puedes hacer pull o push
Ver si puedes descargar cambios (pull):
git pull origin main

 Ver si puedes subir cambios (push):
git push origin main


 ¿Cómo autenticarme en GitLab?

Si Git te pide credenciales cada vez que haces git pull o git push, puedes hacer lo siguiente:

Método 1: Usar un Token de Acceso Personal (PAT)
En GitLab, ve a:
Configuración → Access Tokens → Crear un nuevo token con permisos de repo y write.

Luego, en la terminal, usa:
git remote set-url origin https://oauth2:TOKEN_AQUI@gitlab.com/usuario/proyecto.git
(Sustituye TOKEN_AQUI con tu token generado y usuario/proyecto.git con tu repositorio.)


Clonar un repositorio si aún no lo tienes en local
git clone https://gitlab.com/usuario/proyecto.git

Resumen:

Usa git remote -v para verificar la conexión con GitLab.
Usa git remote add origin URL para conectar tu repositorio local a GitLab.
Usa git pull y git push para verificar acceso.
Si Git pide autenticación, usa un Token de Acceso Personal (PAT).
Si aún no tienes el repo en tu PC, usa git clone URL.

\\Cambiar a una rama remota
Si la rama ya existe en local, simplemente usa:
git checkout nombre-de-la-rama
(Si git checkout no funciona, usa git switch nombre-de-la-rama.)

\\Traer una rama remota si aún no está en local
git fetch

\\Después, crea una copia local de la rama remota y cámbiate a ella:
git checkout -b nombre-de-la-rama origin/nombre-de-la-rama
O con switch:
git switch --track origin/nombre-de-la-rama


\\Ver en qué rama estás actualmente
git branch --show-current

\\esto lista todos los archivos de una rama
git ls-files


Resumen:

Usa git branch -r para ver las ramas remotas.
Usa git fetch para actualizar la lista de ramas.
Usa git checkout -b nombre-rama origin/nombre-rama para crear la rama local desde la remota.
Usa git switch nombre-rama para cambiar de rama.



\\Crear una rama desde la terminal (Git) y subirla a GitLab
Asegúrate de estar en la rama desde donde quieres crear la nueva rama (por ejemplo, main o desarrollo):
git checkout main

\\también puedes usar git switch main en versiones nuevas de Git.

\\Crea la nueva rama localmente:
git branch nombre-de-la-rama
O directamente cambia a la nueva rama:
git checkout -b nombre-de-la-rama
si la rama ya esta creada en el local solo cambiala
git checkout  nombre-de-la-rama
Sube la nueva rama a GitLab remoto:
git push -u origin nombre-de-la-rama
El parámetro -u (o --set-upstream) enlaza la rama local con la remota, para que en el futuro solo necesites usar git push sin especificar la rama.

\\\\\\\\\\\\\\\\\\\ comando git help 

Estas son comandos comunes de Git utilizados en diversas situaciones:

Iniciar un área de trabajo (ver también: git help tutorial)
clone → Clonar un repositorio en un nuevo directorio.

init → Crear un repositorio Git vacío o reinicializar uno existente.

Trabajar en los cambios actuales (ver también: git help everyday)
add → Agregar contenido de archivos al índice.

mv → Mover o renombrar un archivo, directorio o enlace simbólico.

restore → Restaurar archivos del árbol de trabajo.

rm → Eliminar archivos del árbol de trabajo y del índice.

Examinar el historial y el estado (ver también: git help revisions)
bisect → Usar búsqueda binaria para encontrar el commit que introdujo un error.

diff → Mostrar cambios entre commits, entre un commit y el árbol de trabajo, etc.

grep → Imprimir líneas que coincidan con un patrón.

log → Mostrar registros de commits.

show → Mostrar varios tipos de objetos.

status → Mostrar el estado del árbol de trabajo.

Expandir, marcar y ajustar el historial común
backfill → Descargar objetos faltantes en una clonación parcial.

branch → Listar, crear o eliminar ramas.

commit → Registrar cambios en el repositorio.

merge → Unir dos o más historiales de desarrollo.

rebase → Reaplicar commits sobre otra base.

reset → Restablecer el HEAD actual a un estado específico.

switch → Cambiar de rama.

tag → Crear, listar, eliminar o verificar una etiqueta firmada con GPG.

Colaborar (ver también: git help workflows)
fetch → Descargar objetos y referencias desde otro repositorio.

pull → Descargar e integrar cambios desde otro repositorio o una rama local.

push → Actualizar referencias remotas junto con los objetos asociados.

📌 Usa los siguientes comandos para más ayuda:

git help -a y git help -g → Listan los subcomandos disponibles y algunas guías conceptuales.

git help <comando> o git help <concepto> → Muestra información detallada sobre un comando o concepto específico.

git help git → Proporciona una visión general del sistema Git.
